### Changed

- **BREAKING (operator config)**: `MCP_HTTP_ADDR` environment variable removed. The HTTP listen address now resolves via a simpler chain: CLI `-addr` flag > `PORT` env > `:7654` hard default. Why: `MCP_HTTP_ADDR` and `PORT` did the same thing with different priorities, and `MCP_HTTP_ADDR > PORT` was a footgun — operators on PaaS platforms (Railway / Heroku / Fly / Render) who set both got the `MCP_HTTP_ADDR` value silently, even though the platform's healthcheck routed to its own `PORT`, producing "service unavailable" healthcheck failures on every deploy. Migration: operators with `MCP_HTTP_ADDR` set must unset it. On PaaS the platform sets `PORT` automatically — leave it alone. On local docker-compose or bare-metal, use the `-addr` CLI flag or `PORT` env var. Affected files: `cmd/server/main.go` (removed the env lookup, simplified resolution logic + comment), `docker-compose.yml` (removed the redundant `MCP_HTTP_ADDR: ":7654"` env — the `-addr=:7654` CLI flag in `command:` is sufficient), `.env.example` (removed the `MCP_HTTP_ADDR` line, replaced with a `PORT` documentation comment), `docs/deployment.md` (env-vars table updated). `cmd/server/main_test.go` comment updated to reflect that `envOrDefault` now serves only `-transport`.
